# GraphSentinel AI

**An incident-response agent team whose brain is a FalkorDB graph.** Given an open incident, three agents follow
connections across services, deployments, people, documents and past decisions to find the likely root cause, explain
the path, propose a rollback, and *remember what they learn*.

**Tracks entered:** 1 · Agents That Act on Connected Data &nbsp;|&nbsp; 2 · Agent Memory & Coordination &nbsp;|&nbsp; 3 · Company Brain

> **Data:** 100% synthetic (fictional "Acme Commerce"), generated by [app/seed.py](app/seed.py). No private or restricted data is used.
>

## Why the graph is not decoration
Remove FalkorDB and nothing works: root-cause candidates come from variable-length `DEPENDS_ON*0..3` traversals,
similar incidents from shared `Symptom` nodes, owners/experts from `OWNS/MEMBER_OF/RESOLVED` edges, decisions traced to
documents via `RECORDED_IN`, agent hand-offs are `Task` nodes, and memory is `Episode`/`Fact` nodes that change future rankings.

## Graph data model
```
(Team)-[:OWNS]->(Service)-[:DEPENDS_ON]->(Service)
(Person)-[:MEMBER_OF]->(Team)         (Person)-[:AUTHORED]->(Deployment)-[:DEPLOYED_TO]->(Service)
(Incident)-[:AFFECTS]->(Service)      (Incident)-[:HAS_SYMPTOM]->(Symptom)
(Deployment)-[:CAUSED]->(Incident)    (Person)-[:RESOLVED]->(Incident)
(Decision)-[:RESOLVES]->(Incident)    (Decision)-[:ABOUT]->(Service)  (Decision)-[:MADE_BY]->(Person)
(Decision)-[:RECORDED_IN]->(Document)-[:DOCUMENTS]->(Service)
(Procedure)-[:APPLIES_TO]->(Symptom)
── memory & coordination ──
(User{tenant})-[:HAD]->(Episode)-[:CONCERNS]->(Incident), (Episode)-[:CONCLUDED_ON]->(Service)   # episodic
(Fact{tenant,confirmations})-[:ABOUT]->(Service|Symptom)                                          # semantic
(Procedure)                                                                                       # procedural
(Agent)-[:PRODUCED]->(Task)-[:HANDED_TO]->(Agent)                                                 # shared state
(Agent)-[:PROPOSED]->(Action)-[:TARGETS]->(Deployment)                                            # actions
```
**One graph per tenant:** each tenant gets its own FalkorDB graph (`graphsentinel_<tenant>`, e.g. `graphsentinel_acme`, `graphsentinel_globex`) in the same instance, using FalkorDB multigraph. Company knowledge and agent memory live inside that graph, so one tenant's Cypher cannot match another tenant's nodes. Tenants are set with the `TENANTS` env var (default `acme,globex`), and unknown tenants get a 404.

## Queries & algorithms
All Cypher is in [app/queries.py](app/queries.py): `CANDIDATES` (multi-hop), `SIMILAR`, `BLAST_RADIUS`, `EXPERTS`,
`DECISIONS_FOR_SERVICE`, handoff/episode/fact queries, and `algo.pageRank('Service','DEPENDS_ON')` for criticality, and `shortestPath()` (BFS) to produce the evidence path from the affected service to the suspect.

## How the agents work
1. **TriageAgent** – incident → blast radius (multi-hop) + PageRank criticality → writes a `Task` to the graph.
2. **RootCauseAgent** – *reads that Task from the graph*, finds recent deployments along dependency paths, scores
   `recency + proximity + history (similar incidents) + learned memory`, and uses `shortestPath` for the explainable path.
3. **RemediationAgent** – finds on-call owner, experts, decisions + source docs, runbook; proposes a rollback `Action`
   (human approves – nothing is executed).
4. **Learning loop** – "Confirm root cause" writes `CAUSED`, a new `Decision`, and strengthens a `Fact`; the next
   similar incident ranks that pattern higher (see `tests/test_agent.py::test_memory_and_learning`).

## Run locally

### Option A — no Docker (embedded FalkorDB via `falkordblite`)
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt falkordblite
FALKORDB_LITE_PATH=./dev.db uvicorn app.main:app --port 8000
open http://localhost:8000          # graph auto-seeds on first start
```

### Option B — Docker Compose (FalkorDB server + browser UI + app)
```bash
cp .env.example .env
docker compose up --build           # FalkorDB :6379, FalkorDB Browser :3000, app :8000
open http://localhost:8000
```

### Option C — FalkorDB Cloud
```bash
FALKORDB_HOST=<host> FALKORDB_PORT=<port> FALKORDB_USERNAME=<user> FALKORDB_PASSWORD=<password> \
  uvicorn app.main:app --port 8000
```

### Tests
```bash
pip install falkordblite
pytest -q            # 8 tests: health, multi-hop root cause, memory/learning, per-tenant graph isolation, unknown tenant, shortest path, company brain
```

### Demo path
1. Click **INC-201**: the trace and evidence graph show the 3-hop path `checkout-service → payments-api → fraud-service`.
2. Click **Confirm root cause**. This writes `CAUSED`, a new `Decision`, and strengthens a `Fact`.
3. Click **INC-202** and watch the `memory` score component change.
4. Change the `tenant` box to `globex`: a separate graph with none of acme's learned memory. Ask "who owns payments-api?" and the answer cites graph rows.
5. Approve the proposed rollback: only the `Action` node's status changes, and nothing is executed.

## Deploy (Render + FalkorDB Cloud)
1. Create a free FalkorDB Cloud instance and note its host, port, username and password.
2. On Render, choose New → Web Service (or Blueprint from [render.yaml](render.yaml)) and connect this repo with the Docker runtime.
3. Set `FALKORDB_HOST`, `FALKORDB_PORT`, `FALKORDB_USERNAME` and `FALKORDB_PASSWORD`. `GRAPH_NAME` defaults to `graphsentinel`.
4. Open the Render URL. An empty graph is seeded automatically on startup. `/health` returns node and edge counts.

## Honest limitations
- Recommendation-only: approving a rollback records approval in the graph and executes nothing.
- Root-cause scoring is a transparent heuristic (`recency + proximity + history + memory`), not a causal proof. Results are presented as likely causes.
- Tenants are isolated by separate graphs, but there is no authentication. Anyone can pick a tenant name, and only a fixed list is allowed.
- There is no vector or embedding search. Similarity comes from shared `Symptom` nodes.
- There is no authentication. The demo uses a fixed `demo-user`.
